- **Kestrel (MIT)** is a native Rust Android client with an SDK-first mod system, but its documented game target is Minecraft Java 26.3. It is not Bedrock and has not been independently build/device-verified here; no code was reused.
- **Starling (MIT)** is an actively developed Android port of Minecraft Java 26.3 with a mod SDK. This demonstrates a standalone Android game-client architecture, but it does not target Bedrock 1.26.50.4, so it is not a base for SparkVisuals.
- **Alex (MPL-2.0)** is a cross-edition C# client project, but the maintainer states it is no longer maintained; its listed Bedrock support is 1.19.10 and Android remains planned. It is not a practical target.
- **Selaura (GPL-3.0)** lists Android 9+ ARM64 support and has a separate Android launcher, but it is a Bedrock modding framework/client modification, not a verified standalone integrated client route. The user's no-mod-loader/no-injection constraints exclude it; no source was copied.
- **M9CHKO/bedrock-protocol** is useful protocol/network infrastructure but its README explicitly asks publishers to add a project license (no license declaration verified), and its version table ends at 1.26.20. It is not a game renderer or supported interface to the installed Bedrock app. Do not reuse its code without a license.
- Verified the Mojang stable protocol reference: Bedrock 1.26.50 is protocol 2193 (the patch .4 does not establish a different protocol). This does not imply client implementation or device compatibility.
- Host validation: reconstructed the CMake test target from retrieved repository files and compiled/reran the two native-core tests with GCC 14.2/CMake; CTest reported 2/2 passed. This is a local host-only check of the retrieved core/test files, not the official GitHub workflow, Android SDK build, native Preloader SDK compile, or in-game runtime test. Network access to download the repository archive was unavailable.

It is still a companion prototype, not an integrated client.
- Conclusion: no new candidate satisfies Bedrock 1.26.50.4 + standalone integrated APK + no packs/addons/mod package + no process modification. Research-only; no game-integration code added.

## 2026-11-23 — Cinnabar Android candidate discovered and verified

Release API contains Android APK assets for the 2026-11-22 nightly and v0.2.1 beta; APK sizes are 93,878,361 and 101,554,375 bytes respectively. The official separate mod advertises 39 modules but source is not public in the inspected listing and was not copied. Built-in SparkVisuals functionality would need to be compiled into the client source, not shipped as a separate module.
- No code copied, forked, or device-tested; research only. Full assessment is in CINNABAR_ANDROID_CANDIDATE.md.

## 2026-11-23 — protocol backport scope checked
- Mojang's stable changelog shows 64 protocol changes from 1.26.51 (2193) to 1.26.60 (2225): 8 packets added and 56 changed. Examples: ActorEvent enum values renumbered, BuildPlatform/GameType enums changed, AddActor/AddPlayer gained passenger-block data, camera fields became optional, environment-attribute and sound-event packet schemas changed.
- This confirms Cinnabar target 1.26.60 cannot be downgraded to 1.26.50.4 by changing the version constant. Actual code-level backport estimate remains unknown; no compatibility code was written.
- Source: https://mojang.github.io/bedrock-protocol-docs/changelog/ (1.26.60 and 1.26.51 sections).

It has world rendering, player controls, inventory/chat/menu UI and connects via Acacia's client/bot layer. MIT workspace license.
- Acacia target is Bedrock 1.26.51 / protocol 2193; stable 1.26.50 uses protocol 2193 too. This shared wire number is encouraging but does not prove exact 1.26.50.4 compatibility or content/registry parity. Android packaging, cross-build, APK and device runtime are not documented/verified.
- Renderer uses Mojang/bedrock-samples vanilla look/resource assets and bakes them. Literal no-resource-pack policy disqualifies it unless user explicitly clarifies that base-game assets are acceptable. No fork or source reuse.
